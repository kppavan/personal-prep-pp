### There can be 50 event hanlers added per form

```javascript
1. formContext starting point to access fields, controls and data on the form

function onLoad(executionContext){
  var formContext = executionContext.getFormContext();
}

2. getAttribute() - Access field values

var name = formContext.getAttribute('logical name').getValue();

formContext.getAttribute('logical name').setValue('some value');

3. getControl() (Access UI controls)

Used to show/hide fields or disable them.

Example

formContext.getControl("creditlimit").setVisible(false);

Disable field

formContext.getControl("creditlimit").setDisabled(true);
4. setRequiredLevel()

Used to make fields required dynamically.

formContext.getAttribute("emailaddress1").setRequiredLevel("required");

Values:

"none"

"recommended"

"required"

Scenario:
If customer type = VIP → Email required

5. addOnChange() (Attach event handlers)

Used to trigger logic when a field value changes.

formContext.getAttribute("revenue").addOnChange(calculateDiscount);

Interview explanation:
Used to run business logic automatically when a field changes.

6. setNotification() / clearNotification()

Used to show validation messages on the form.

formContext.getControl("emailaddress1")
.setNotification("Email is mandatory");

Clear message

formContext.getControl("emailaddress1")
.clearNotification();
7. Xrm.Navigation.openAlertDialog()

Used to show popup messages to users.

Xrm.Navigation.openAlertDialog({
    text: "Please enter email"
});
8. Xrm.WebApi.retrieveRecord()

Used to retrieve Dataverse records using JavaScript.

Xrm.WebApi.retrieveRecord("account", accountId, "?$select=name")
.then(function(result){
    console.log(result.name);
});

Scenario:
Get account credit limit when account is selected.

9. Xrm.WebApi.createRecord()

Used to create records from JavaScript.

var data = {
   name: "Test Account"
};

Xrm.WebApi.createRecord("account", data);
10. Xrm.WebApi.updateRecord()

Used to update existing records.

var data = {
   name: "Updated Name"
};

Xrm.WebApi.updateRecord("account", accountId, data);

```

## Command Bar Buttons

### Places where buttons can be added

- View
- Form
- SubGrid

### Types of buttons that can be created from Command bar designer from model driven app.

- Single Action button/ Command - clicking on it will do some action ex: submit, approve etc

- Split Button - Button that has two clickable areas, main area -> runs the default action, dropdown area -> shows additional commands.

- Flyout Button (Dropdown)
  A button that only opens a menu with multiple options.

Behaviour

- Clicking button shows a list of commands, No default action on the command itself.

- Group:
  A container used to group related buttons together in the command bar.

Visual Summary

| Type          | Behavior                          | Example        |
| ------------- | --------------------------------- | -------------- |
| Button        | Single action                     | Submit         |
| Split Button  | Default action + dropdown options | Save ▼         |
| Flyout Button | Only dropdown menu                | Actions ▼      |
| Group         | Container for buttons             | Approval Group |

### Types of command (JS and Power Fx)

- Command Bar buttons can run logic written in Javascript and also Power FX.
  Power FX has some limitations compared to full functionality provided by JS. ex calling web api.

### Power fx Basics for command Bar | Notify, Patch, Confirm Dialog, Navigate, Launch

1️⃣ Show Notification

Display a message when the button is clicked.

```powerfx
Notify("Record processed successfully", NotificationType.Success)
```

Other types:

```powerfx
NotificationType.Success

NotificationType.Error

NotificationType.Warning

NotificationType.Information
```

Example:

```powerfx
Notify("Something went wrong", NotificationType.Error)
```

2️⃣ Update a Field Value

Update a field in the current record.

```powerfx
Patch(
Accounts,
Self.Selected.Item,
{ Status: 'Status (Accounts)'.Active }
)
```

Example scenario
Approve button → set Status = Approved

3️⃣ Conditional Logic (If Statement)

```powerfx
If(
Self.Selected.Item.Amount > 10000,
Notify("Manager approval required", NotificationType.Warning),
Notify("Approved", NotificationType.Success)
)
```

Useful for:

validations

conditional actions

4️⃣ Open a Page or Navigate

```powerfx
Navigate("Account Main Form")
```

Or open a record:

```powerfx
Launch("https://yourcompany.com")
```

5️⃣ Refresh Data
Refresh(Accounts)

Used after updates to reload the data grid.

6️⃣ Run a Power Automate Flow

You can call flows created in Microsoft Power Automate.

Example:

```powerfx
MyApprovalFlow.Run(Self.Selected.Item.Account)
```

Typical use:

Send email

Start approval

Integration with external systems

7️⃣ Select Record From Grid

When button is on a grid command bar:

```powerfx
Self.Selected.Item

Example:

Notify(
Self.Selected.Item.'Account Name',
NotificationType.Information
)
```

8️⃣ Loop Through Selected Records

```powerfx
ForAll(
Self.Selected.AllItems,
Patch(Accounts, ThisRecord, { Status: "Processed" })
)
```

Used when multiple records are selected.

9️⃣ Validate Before Action

```powerfx
If(
IsBlank(Self.Selected.Item.Email),
Notify("Email is required", NotificationType.Error),
Notify("Valid record", NotificationType.Success)
)
```

🔟 Combine Multiple Actions

```powerfx
Patch(
Accounts,
Self.Selected.Item,
{ Status: "Approved" }
);
Notify("Record approved", NotificationType.Success);
Refresh(Accounts)
```

- ; allows multiple actions in sequence.

### Adding Dependency for Web resource and attribute dependency

In Microsoft Dynamics 365 / Microsoft Power Apps Model-Driven Apps, when you add a JavaScript web resource, you can define dependencies so the platform knows what components must exist for that web resource to work properly.

There are two common dependency types related to a web resource:

- Web Resource Dependency

- Attribute Dependency

Both help the system track relationships between components, especially during solution export/import.

Web Resource (JavaScript)
│
├─ Web Resource Dependency
│ └─ helperScript.js
│
└─ Attribute Dependency
├─ name
├─ emailaddress1
└─ telephone1

| Dependency              | Meaning                                | Example        |
| ----------------------- | -------------------------------------- | -------------- |
| Web Resource Dependency | Script depends on another web resource | helper JS file |
| Attribute Dependency    | Script uses specific form fields       | name, email    |

Web Resource Dependency → Script depends on another file

Attribute Dependency → Script depends on a field
